# General review, 2026-11-12

## Delivered

- Completed the pending arm posture and item picture fixes. Mushroom/flower pictures retain transparency; shaped items have their own silhouettes; ice also gets an inventory texture.
- Mining no longer discards drops when the backpack is full: the block stays until the complete batch fits. Breaking a chest/furnace treats its contents and block as one batch.
- Animal products are collected atomically. Partial room can no longer duplicate wool, discard a bonus feather or wear shears on a failed collection.
- Removed the temporary global game-state debug handle and replaced the old partial-collection branches.
- Models now release owned GPU resources when removed or replaced. Shared colour materials and sprite geometry remain alive. Recolouring wool and replacing labels release the old resources.
- Both enemy and player arrows are removed when switching worlds; bow/shield draw state resets too. A culled animal cannot remain the current target.
- Added `ARCHITECTURE.md` to explain runtime ownership, persistence, bridges and build generation.

## Review coverage

Existing suites cover terrain, collisions, liquids, lighting, survival, recipes, creatures, weather, controllers, touch and persistence.

A local ESLint pass (59 files, zero findings) checked undefined/unused variables, unreachable code, duplicate keys and constant conditions. Export-reference and smoke-accessor scans found no additional proven dead code: exported constants without outside production consumers are still used inside their modules or by rule tests. No speculative removal of working systems or translation entries.

## Remaining limits and next improvements

1. Validate on the physical iPad: finger mining and workbench usability, a sustained session for frame rate/heat/memory, physical controllers, and real iCloud sync between two devices.
2. Complete phase 0b (fixed-step simulation) and 0c (one block registry) before expanding the world. `main.js` still combines many responsibilities; extract by feature with regression tests rather than a blanket rewrite.
3. Add rolling backups alongside a storage migration before larger worlds. This review does not change save format or storage location.
4. Loose loot is still not a world entity. Mining and animal products are protected, but loot from combat/hunting and fishing can still be lost when full. A persistent dropped-item system is phase 4 work.
5. Distribution signing/notarization, Mac Intel and real-device performance are separate from local/simulator build success.

No claim of 100% coverage or completion of the v3 roadmap. Villages, circuits, magic and multiplayer remain planned features, not regressions in this release.


## Follow-up: persistent overflow rewards

- Combat, hunting and fishing now keep overflow in the existing orange ground bags, near the player (the last safe location when in lava). Nearby bags merge and use the existing version 2 world representation. No storage migration.
- The complete transaction is planned before mutating inventories. If all 64 ground bags have no available space, the final defeat/catch is deferred; a player falling asleep retains their inventory rather than losing it.
- Removed the old ten-bag truncation on load. Worlds beyond the supported limit are rejected, not silently reduced. Unit coverage checks twelve saved bags and worn tools.
- 140 unit tests passed and 224 integrated checks passed on macOS. Static review: 61 JavaScript files, zero findings with the same rules as above. iOS UI tests also passed on iPhone 17e and iPad Pro 11-inch M5 (iOS 26.5), including landscape/portrait controls and the shared integrated suite.
- This closes remaining limit 4 above for combat/hunting/fishing rewards. Individual loose-item render models, fixed-step simulation, backups and physical-device validation remain separate tasks.
