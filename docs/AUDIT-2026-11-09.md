# General audit, 2026-11-09

This audit compares the current repository with `prompt-bieltructor-v2 10.33.53.md`. Earlier notes describing lighting, tool wear, lava and the input module as missing are outdated: these systems are implemented. Passing tests does not prove 100% reliability.

## Corrections

- Moving tools into/out of chests, emptying a chest and collecting a recovery backpack preserve durability. Previously these paths silently repaired tools.
- Breaking a chest or furnace now checks capacity atomically. If its contents do not fit, the container and backpack stay intact and the existing full-backpack message appears. Previously excess items disappeared.
- Imported recovery backpacks validate item identifiers, stack counts and wear; furnace outputs reject unknown items.
- Cloud synchronization rejects corrupt or duplicate remote entries instead of interpreting them as absent worlds and uploading over them.
- Failed conflict uploads retain the conflict for retry, report unavailability and do not mark the world as synchronized. Repeated clicks, disabled sync and active gameplay are guarded.
- Null sync metadata and native bridge exceptions are recoverable. Native request timeout callbacks are cancelled after replies.
- Removed external navigation from the game credits, matching the offline child-facing brief; removed the now-unused native external-link/popup handlers and UI delegate wiring. Credits remain visible as plain text.
- README no longer claims both partial completion and complete implementation.

## Review scope and cleanup

Reviewed the current source/module inventory, inventory and crafting rules, save validation, synchronization, container/recovery integration, input declarations, native bridges, build scripts, CI configuration and the existing phase-by-phase implementation record. Searched source declarations and imports for unused symbols and checked apparent candidates against tests and native callbacks. No additional whole module or imported symbol was established as dead code. The HELD/TAPS action lists are used by contract tests; native callbacks and smoke checks are entry points, not dead code. They were retained.

## Outstanding work and differences

- Real iPad/iPhone play sessions, sustained fps/temperature measurements, audio listening checks, physical controllers and real iCloud synchronization across devices are still required. Simulator success is not evidence for these.
- ~~iCloud compare-and-write and deletion~~ Resolved in the follow-up below. Real iCloud between devices is still untested.
- The nearest installed small iPhone simulator is 17e, not the requested iPhone SE. Intel Macs and signed distribution are unverified.
- Medium/large islands remain 97/129 blocks rather than 96/128 to preserve centered-world geometry. Bees and fish remain ambient rather than fully persistent/breedable animals. Shelter/tutorial goals remain simplified.
- `main.js` remains large and combines UI, input dispatch and gameplay. Further extraction should follow behavioral boundaries with regression coverage, without a rewrite simply to reduce line count.

## Follow-up (same day)

- **iCloud compare-and-write:** every save carries the `updatedAt` the game saw when listing, or null for a new file. `CloudBridge.swift` reads and writes inside one `NSFileCoordinator` write and refuses with `{ ok: false, changed: true }` if the file changed; the game retries a few seconds later instead of reporting a failure.
- **iCloud deletion:** deleting a world writes a marker (`{ id, deleted: true, updatedAt }`) instead of removing the file. Other devices delete their copy if they have not played it since the last sync, and keep it and send it back up if they have. A deletion made offline is remembered (`biel-deleted`) and finished on a later sync. The unused native `delete` action was removed.
- **World list:** every world can be renamed and exported from the list, not only the open one.
- **Compass and map items** (listed among the brief's items): the compass says how far home is and in which direction; the map opens the island map.
- **Dead code:** a full pass (exports, strings, CSS classes, Swift) found only one export used nowhere else (`HUNT`), now private.

Validation: 125 Node tests and 194 Mac smoke checks passed; XCUITest passed on iPad Pro 11-inch, iPhone 17e and iPhone 17 Pro Max simulators. The new cloud rules are tested with two pretend devices sharing one folder (`tests/persistence.test.js`) and in the smoke suite. Two real devices with a real iCloud account have not been tried.

## Third follow-up (2026-11-12): workbench squares, mining with a finger

Asked for after playing on a real iPad: "the box with nine squares" and "a mining mode".

- **Workbench with nine squares:** using a workbench (or "Open the workbench" in the backpack when one is near) opens nine squares. A tap on something in the backpack puts one in the next free square, a tap on a square empties it, and what the squares make shows next to them. Positions do not matter, only what is there (`gridMatches` in `src/recipes.js`). When the same things make two recipes (pickaxe or axe, door or trapdoor) both are offered. The recipe book below fills the squares, tools in their shape. What sits in the squares stays in the backpack until the craft, so nothing can be lost by closing the screen or the app.
- **Mine / Build switch on touch screens:** a button next to the backpack. In Mine, a finger kept still on a block for a fifth of a second breaks it and keeps digging what is behind; dragging the finger away stops the mining and looks around again. In Build, a tap places the block or uses a door, chest, furnace or workbench. The Break and Build buttons still work. A finger now has to move ten pixels before it counts as a drag, so a tap that wobbles is still a tap.
- **Bugs found on the way:**
  - With food in the hand, Build always tried to eat first. So with a mouse, a controller or the Build button, an apple could not tame a horse, a fish could not befriend the cat, carrots and potatoes could not be planted, a mushroom could not be placed and nothing could be opened. Animals, usable blocks and planting now come before eating.
  - A golden apple was used up even with full hearts and no hunger.
  - Honey and its bottle were lost when the backpack was full; so were eggs, milk and wool, while the animal still started its wait. Now the bottle comes back and the animal can be asked again.
  - A screen with a long list (the recipe book, the furnace while cooking) jumped back to the top each time it was redrawn. It now stays where it was.
  - A slow mouse drag of one pixel at a time never counted as a drag and ended as a click.
- **Dead code:** the `HELD` and `TAPS` lists in `src/input/actions.js` were read only by tests, never by the game; they and the test that only checked them are gone. A one-off five-second probe left in the iOS debug log was removed. ESLint (`no-unused-vars`, `no-unreachable`) and a pass over exports, texts and CSS classes found nothing else.
- **Build scripts:** every build moved the previous one into `build/archive` (214 copies, 450 MB on the author's Mac). They now replace it. The signing team lives in `project.yml`, so regenerating the project keeps it.

Validation: 125 Node tests and 211 Mac smoke checks passed (14 new: the nine squares, mining with a finger, building with a tap). The workbench screen and the switch were checked by eye in a browser. XCUITest passed on iPad Pro 11-inch, iPhone 17e and iPhone 17 Pro Max simulators. Mining with a real finger on a real iPad has not been tried yet.
