# General audit, 2026-11-09

This audit compares the current repository with `prompt-bieltructor-v2 10.33.53.md`. Earlier notes describing lighting, tool wear, lava and the input module as missing are outdated: these systems are implemented. Passing tests does not prove 100% reliability.

## Corrections

- Moving tools into/out of chests, emptying a chest and collecting a recovery backpack preserve durability. Previously these paths silently repaired tools.
- Breaking a chest or furnace now checks capacity atomically. If its contents do not fit, the container and backpack stay intact and the existing full-backpack message appears. Previously excess items disappeared.
- Imported recovery backpacks validate item identifiers, stack counts and wear; furnace outputs reject unknown items.
- Cloud synchronization rejects corrupt or duplicate remote entries instead of interpreting them as absent worlds and uploading over them.
- Failed conflict uploads retain the conflict for retry, report unavailability and do not mark the world as synchronized. Repeated clicks, disabled sync and active gameplay are guarded.
- Null sync metadata and native bridge exceptions are recoverable. Native request timeout callbacks are cancelled after replies.
- Removed external navigation from the game credits, matching the offline child-facing brief; removed the now-unused native external-link/popup handlers and UI delegate wiring. Credits remain visible as plain text.
- README no longer claims both partial completion and complete implementation.

## Review scope and cleanup

Reviewed the current source/module inventory, inventory and crafting rules, save validation, synchronization, container/recovery integration, input declarations, native bridges, build scripts, CI configuration and the existing phase-by-phase implementation record. Searched source declarations and imports for unused symbols and checked apparent candidates against tests and native callbacks. No additional whole module or imported symbol was established as dead code. The HELD/TAPS action lists are used by contract tests; native callbacks and smoke checks are entry points, not dead code. They were retained.

## Outstanding work and differences

- Real iPad/iPhone play sessions, sustained fps/temperature measurements, audio listening checks, physical controllers and real iCloud synchronization across devices are still required. Simulator success is not evidence for these.
- iCloud still lacks coordinated compare-and-write protection against another device changing a file between listing it and saving it. Failed cloud deletion can also allow a world to return from the cloud later. The local conflict planner tests do not prove transport safety; JSON exports remain useful independent backups.
- The nearest installed small iPhone simulator is 17e, not the requested iPhone SE. Intel Macs and signed distribution are unverified.
- Medium/large islands remain 97/129 blocks rather than 96/128 to preserve centered-world geometry. Bees and fish remain ambient rather than fully persistent/breedable animals. Shelter/tutorial goals remain simplified.
- `main.js` remains large and combines UI, input dispatch and gameplay. Further extraction should follow behavioral boundaries with regression coverage, without a rewrite simply to reduce line count.

## Recommended next steps

1. Validate a longer real-device session with Gabriel: building, full inventory, sleeping, fainting, relaunching and JSON export/import.
2. Implement coordinated native cloud writes and deletion reconciliation before treating cross-device iCloud as fully reliable.
3. Improve child-facing tutorial feedback and building usability based on that session; then separate container/persistence UI from the main loop.

Keep the offline, single-player focus. Additional content should follow observed needs rather than adding more systems before validating those already present.
